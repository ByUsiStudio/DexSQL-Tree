# 0.6.0 计划：从能用到顺手

1.0.0 收掉了目录体积、缓存碎片与首次使用的门槛：`start` 一条命令给出规模与三个结论，报错带最近邻建议，一个输入一份缓存。

剩下的问题集中在三处。

## 一、GUI 仍然比 CLI 落后一步

CLI 有 `start`，GUI 打开时还是一句 placeholder。空状态下应该放三张可点击的示例卡片（找 URL / 找密码 / 看调用链），点击即填 SQL 并运行；`tables` 面板要显示列说明，随 `DEXSQL_TREE_ZH` 切换中英文。

## 二、模板还不够像"任务"

现有 12 个模板是查询形态（callers、callees、strings-with-callers），不是问题形态。缺四个直接对应用户说法的：

| 模板 | 对应的问题 |
| --- | --- |
| `find-urls` | 这个包里有没有写死的接口地址 |
| `find-secrets` | 有没有硬编码的 key、token、密码 |
| `find-entrypoints` | 从哪个 Activity / Service 进来 |
| `trace-permission` | 这个权限是在哪里申请的 |

它们和现有模板共用同一个渲染器，`start` 与 GUI 卡片都指向这几个名字。

## 三、长驻服务还是单连接

`serve` 每个目录一条只读连接（`SetMaxOpenConns(1)`），两个客户端同时查会排队。可行的做法是磁盘目录开 WAL 并按请求取连接；内存目录无解，只能在文档里说清楚。

## 不在本版范围

- SQL 语法高亮、结果导出——锦上添花。
- `debug_positions` 打包：会改变 `debug_positions` 的 SQL 契约，需要单独设计查询接口。
- 列式存储：1.0.0 之后主力查询在 1–3 s，换执行引擎的收益不足以抵消丢掉完整 SQL 的代价。

## 衡量方式

给一个没接触过这个工具的人一句"用它看看这个 APK 里有没有硬编码的接口地址"，GUI 与 CLI 各一次。两次都不需要打开 README，这一版就算达标。
