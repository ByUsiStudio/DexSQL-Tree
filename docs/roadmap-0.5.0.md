# 0.5.0 计划：新手体验

0.2.0 让查询变简单，0.3.0 让打开变快，0.4.0 让打开只做这次查询需要的事。0.5.0 的目标是让第一次使用的人在**五分钟内拿到第一个有用结论**，而不是先读完整篇 README。

现状的问题很具体：

1. 打开空目录时，CLI 只打印一句"至少需要一个 --input 参数"，没有告诉人下一步该敲什么。
2. `tables` 有 56 张表，新用户不知道从哪张开始；`v_methods` 这类捷径藏在文档第 5 节。
3. 报错只描述现象（`no such column: boom`），不给替代写法。
4. GUI 空白时只有一句 placeholder，没有可点击的示例。
5. 文档是中文为主的技术说明，缺少"我想找 URL / 找密码 / 找入口"这类任务导向的入口。

## 验收标准

一条命令走完首次体验，不需要提前读文档：

```bash
dexsql-tree start app.apk
```

它应该做四件事：

1. 打印这个包的规模与"最值得先看的三件事"；
2. 直接跑三条示例查询（最大的类、字符串里的 URL、入口方法），结果用表格输出；
3. 每段结果下面给一句"接着可以试"，附上可直接复制的命令；
4. 结尾提示 `--cache` 能让下次打开快 20 倍。

## 工作项

| 项 | 说明 |
| --- | --- |
| `start` 子命令 | 上面的四步，CLI 与 `serve` 共用同一份"建议"逻辑 |
| 任务导向入口 | `recipes` 增加 `find-urls`、`find-secrets`、`find-entrypoints`、`trace-permission` 四个模板，并在 `start` 里推荐 |
| 错误建议 | 报错时附带一条修复建议：拼错表名给出最近邻，缺列给出 `tables <name>`，语法错给出行号 |
| 表说明双语 | `tables --doc` 与 GUI 的 schema 面板显示中英文说明，随 `DEXSQL_TREE_ZH` 切换 |
| GUI 首次提示 | 空状态下放三个可点击的示例卡片（找 URL / 找密码 / 看调用链），点击即填 SQL 并运行 |
| 文档导航 | README 开头加"我想要…"表格，指向对应命令与章节 |

## 不在本版范围

- SQL 语法高亮、结果导出——锦上添花，等新手路径稳定后再做。
- 注解的按需展开、`debug_positions` 打包——属于引擎侧，见 0.4.0 发布说明的"下一步"。

## 衡量方式

找三个没接触过这个工具的人，只给一句"用它看看这个 APK 里有没有硬编码的接口地址"，观察他们是否需要打开 README。如果三个人都能在不看文档的情况下完成，这一版就达标。
